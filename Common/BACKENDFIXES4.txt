11. GATE CHECK-IN MUST BE ATOMIC

When a ticket is scanned at the gate:

Validate the ticket.
Verify that the ticket exists in the database.
Verify that the ticket belongs to the correct attendee.
Verify ticket status.
Verify whether it has already been checked in.
If valid, create/update the attendance record.
Update the ticket/check-in state in the database.
Return the authoritative database result.
Update the frontend using that result.

The operation must be atomic/transaction-safe.

Prevent two gates or two scanners from successfully checking in the same ticket simultaneously.

Use appropriate database transactions/locking/unique constraints.

12. PREVENT DUPLICATE CHECK-IN

ALREADY_CHECKED_IN

Ticket identifier
Attendee
Previous check-in timestamp
Gate information if available

Do not create another successful attendance record.

The database must enforce this wherever possible instead of relying only on frontend validation.
